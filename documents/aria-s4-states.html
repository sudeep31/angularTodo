Section 4 of 9 ARIA States

4.1

States vs Properties — Recap

As established in Section 3, ARIA attributes divide into two categories. States are the dynamic half — they change at runtime in response to user interaction, data loading, or validation. The accessibility tree reflects every state change immediately, triggering a screen reader announcement or updating the AT's internal model of the page.

Type Values States in this section
Boolean true / false aria-expanded, aria-selected, aria-busy, aria-hidden
Tristate true / false / mixed aria-checked, aria-pressed
Token One of a defined set of string values aria-invalid (grammar/spelling/true/false), aria-current (page/step/…)
Token or Boolean Either a token string or true/false aria-disabled
💡

Key Angular principle: always use [attr.aria-*] bindings. When the bound expression returns null, Angular removes the attribute entirely from the DOM — the correct behaviour for a state that is "not applicable" (e.g., aria-expanded on an element that never has a popup).

4.2

aria-expanded

aria-expanded
Boolean
true — expanded false — collapsed absent — no popup / not applicable

Indicates whether a disclosure widget, accordion panel, tree node, or menu is currently expanded (its controlled content is visible). Set on the trigger (button/header), not on the controlled panel.

Pair with aria-controls so AT can navigate from trigger to panel: aria-controls="panel-id"
NVDA / JAWS: "collapsed" when false, "expanded" when true. VoiceOver: "collapsed" / "expanded" appended to the button name.

Applies to

  • Disclosure button / accordion — toggles a panel below
  • Combobox — indicates whether the suggestion listbox is open
  • Tree node — indicates whether children are shown
  • Navigation menu button — indicates whether a submenu is open
⚠️

Do not set aria-expanded on elements that have no collapsible content. A button that opens a modal uses aria-haspopup="dialog" — not aria-expanded. A navigation link that leads to a new page does not use either. Absent is the correct value when the concept doesn't apply.

Angular 21 — Disclosure / Accordion

TypeScript + HTML 
@Component({
  selector: 'app-accordion-item',
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    <h3>
      <button
        type="button"
        [id]="headingId"
        [attr.aria-expanded]="isOpen()"
        [attr.aria-controls]="panelId"
        (click)="toggle()">
        {{ title() }}
        <svg aria-hidden="true" [class.rotate-180]="isOpen()">...</svg>
      </button>
    </h3>

    <div
      [id]="panelId"
      role="region"
      [attr.aria-labelledby]="headingId"
      [hidden]="!isOpen()">
      <ng-content />
    </div>
  `,
})
export class AccordionItemComponent {
  title  = input.required<string>();
  isOpen = signal(false);

  private idGen = inject(IdGenerator);
  headingId = this.idGen.getId();
  panelId   = this.idGen.getId();

  toggle() { this.isOpen.update(v => !v); }
}
💡

Use [hidden] (not *ngIf / @if) to hide the panel. [hidden] keeps the element in the DOM so aria-controls can always resolve its target. @if removes the element — the target of aria-controls disappears, confusing AT.

4.3

aria-checked

aria-checked
Tristate
true — checked false — unchecked mixed — indeterminate

Represents the checked state of a checkbox, radio button, or checkbox-like custom widget. The mixed value is the ARIA equivalent of the HTML indeterminate property on a native checkbox — used when a "select all" checkbox controls a group where some but not all are checked.

On native <input type="checkbox"> — do not add aria-checked. The browser exposes the native checked state automatically. Only use on custom elements with role="checkbox" or role="menuitemcheckbox".
NVDA: "checked" / "not checked" / "partially checked". JAWS: "checked" / "unchecked" / "partially checked". VoiceOver: "checked" / "unchecked" / "mixed".

The mixed / indeterminate pattern

TypeScript + HTML — "Select all" with indeterminate state 
@Component({
  selector: 'app-todo-list',
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    <!-- Native checkbox — use indeterminate property, not aria-checked -->
    <label>
      <input
        type="checkbox"
        [checked]="allChecked()"
        [indeterminate]="someChecked()"
        (change)="toggleAll($event)">
      Select all todos
    </label>

    <!-- Custom checkbox widget (role="checkbox") -->
    <div
      role="checkbox"
      tabindex="0"
      [attr.aria-checked]="checkedState()"
      (click)="toggleAll()"
      (keydown.space)="toggleAll(); $event.preventDefault()">
      Select all todos
    </div>
  `,
})
export class TodoListComponent {
  todos = signal<Todo[]>([]);

  allChecked  = computed(() => this.todos().every(t => t.completed));
  noneChecked = computed(() => this.todos().every(t => !t.completed));
  someChecked = computed(() => !this.allChecked() && !this.noneChecked());

  // For the custom role="checkbox" widget
  checkedState = computed(() => {
    if (this.allChecked())  return 'true';
    if (this.someChecked()) return 'mixed';
    return 'false';
  });

  toggleAll(event?: Event) { /* toggle all todos */ }
}
4.4

aria-selected

aria-selected
Boolean
true — selected false — not selected absent — selection not applicable

Indicates that an option, tab, row, or grid cell is currently selected. Unlike aria-checked (which is for checkboxes), aria-selected is for selection in widgets like listboxes, tabs, tree views, and grids.

In a tablist: set aria-selected="true" on the active tab, aria-selected="false" on all others. The active tab's panel must be shown; all other panels must be hidden.
aria-selected vs aria-checked: Use aria-selected in selection widgets (listbox, tree, grid, tablist). Use aria-checked in checkbox-like widgets. Never mix them on the same element.
NVDA / JAWS: "selected" appended to the item name. VoiceOver: "selected" added to announcement.

Angular 21 — Tab component

HTML — Accessible tabs with aria-selected 
<div role="tablist" aria-label="Todo filters">
  @for (tab of tabs(); track tab.id; let i = $index) {
    <button
      role="tab"
      [id]="'tab-' + tab.id"
      [attr.aria-selected]="activeTab() === tab.id"
      [attr.aria-controls]="'panel-' + tab.id"
      [tabindex]="activeTab() === tab.id ? 0 : -1"
      (click)="activateTab(tab.id)"
      (keydown)="onTabKeydown($event, i)">
      {{ tab.label }}
    </button>
  }
</div>

@for (tab of tabs(); track tab.id) {
  <div
    role="tabpanel"
    [id]="'panel-' + tab.id"
    [attr.aria-labelledby]="'tab-' + tab.id"
    tabindex="0"
    [hidden]="activeTab() !== tab.id">
    ...panel content...
  </div>
}
💡

Tabs use roving tabindex: only the active tab has tabindex="0"; all others have tabindex="-1". Arrow keys move focus within the tablist; Tab moves to the panel. Implement onTabKeydown to handle ←/→ for horizontal tabs, ↑/↓ for vertical.

4.5

aria-pressed

aria-pressed
Tristate
true — pressed / on false — not pressed / off mixed — partially pressed absent — not a toggle button

Turns a <button> into a toggle button — announcing whether it is currently in the "on" or "off" state. Common for Bold/Italic toolbar buttons, theme toggles, mute buttons, and filter toggles.

aria-pressed vs aria-checked: Use aria-pressed on role="button" elements. Use aria-checked on role="checkbox". They signal different interaction models to AT.
aria-pressed="mixed" is valid but rarely useful. It is for a toggle that controls a group where the state is partially applied (e.g., a Bold button when selected text has mixed bold/non-bold formatting).
NVDA: "pressed" / "not pressed" appended to button name. JAWS: "pressed" / "not pressed". VoiceOver: "selected" (for true) / nothing (for false) — note VoiceOver inconsistency.

Angular 21 — Toggle button pattern

HTML — aria-pressed toggle button 
<!-- Theme toggle -->
<button
  type="button"
  [attr.aria-pressed]="isDarkMode()"
  [attr.aria-label]="isDarkMode() ? 'Switch to light mode' : 'Switch to dark mode'"
  (click)="toggleDarkMode()">
  <svg aria-hidden="true">...</svg>
</button>

<!-- Filter toggle button -->
<button
  type="button"
  [attr.aria-pressed]="showCompleted()"
  (click)="toggleCompleted()">
  Show completed
</button>
<!-- "Show completed, toggle button, not pressed" / "pressed" -->
4.6

aria-invalid

aria-invalid
Token
false — valid (default) true — invalid grammar — grammar error spelling — spelling error

Signals that the value entered by the user does not pass validation. Must be set after the user has had a chance to enter a value — never on first render. Always paired with aria-errormessage (or aria-describedby pointing to an error element) so AT can read the specific error.

Do not set aria-invalid="false" explicitly — the default is false when the attribute is absent. Setting it to false adds noise to the DOM. Use null to remove the attribute when the field is valid.
NVDA: "invalid entry" announced on focus when aria-invalid="true". JAWS: "invalid entry" on focus, then reads the error message. VoiceOver: announces the error message from aria-errormessage / aria-describedby.

Angular 21 — Reactive forms integration

TypeScript — Form state → aria-invalid with signals 
@Component({
  selector: 'app-todo-form',
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    <form [formGroup]="form" (ngSubmit)="submit()">
      <label [for]="titleId">Todo title</label>

      <input
        [id]="titleId"
        formControlName="title"
        [attr.aria-invalid]="titleInvalid() ? 'true' : null"
        [attr.aria-errormessage]="titleInvalid() ? titleErrorId : null"
        [attr.aria-describedby]="titleHintId">

      <p [id]="titleHintId">Maximum 120 characters.</p>

      <p
        [id]="titleErrorId"
        aria-live="polite">
        {{ titleError() }}
      </p>
    </form>
  `,
})
export class TodoFormComponent {
  private idGen   = inject(IdGenerator);
  titleId      = this.idGen.getId();
  titleHintId  = this.idGen.getId();
  titleErrorId = this.idGen.getId();

  form = new FormGroup({
    title: new FormControl('', [Validators.required, Validators.maxLength(120)]),
  });

  // Only show invalid state after the user has touched the field
  titleInvalid = computed(() => {
    const ctrl = this.form.controls.title;
    return ctrl.invalid && (ctrl.dirty || ctrl.touched);
  });

  titleError = computed(() => {
    if (!this.titleInvalid()) return '';
    const errs = this.form.controls.title.errors;
    if (errs?.['required'])   return 'Title is required.';
    if (errs?.['maxlength']) return 'Title must be 120 characters or fewer.';
    return 'Title is invalid.';
  });

  submit() { /* validate & submit */ }
}
4.7

aria-busy

aria-busy
Boolean
false — content is complete (default) true — content is loading / updating

Tells AT to defer reading a region's content until loading is complete. Set aria-busy="true" before updating a large portion of the DOM, then set it back to false (or remove the attribute) when the update is done. Prevents AT from reading partial or intermediate content mid-update.

Combine with a visible loading indicator using role="status" or aria-live="polite" to announce when loading finishes. Screen readers do not automatically announce when aria-busy transitions to false.
When aria-busy="true", AT suppresses updates to the region. When aria-busy switches to false, AT reads the updated content.

Angular 21 — Loading list with aria-busy

HTML 
<section
  aria-labelledby="todo-list-heading"
  [attr.aria-busy]="isLoading() ? 'true' : null">

  <h2 id="todo-list-heading">Your todos</h2>

  @if (isLoading()) {
    <div role="status" aria-label="Loading todos">
      <svg aria-hidden="true" class="animate-spin">...</svg>
    </div>
  } @else {
    <ul>
      @for (todo of todos(); track todo.id) {
        <li>{{ todo.title }}</li>
      }
    </ul>

    <!-- Announce load completion to AT -->
    <div role="status" class="sr-only">
      {{ todos().length }} todos loaded.
    </div>
  }
</section>
4.8

aria-disabled vs disabled

aria-disabled
Boolean
false — enabled (default) true — disabled

Communicates that an element is disabled without removing it from the tab order or preventing keyboard focus. This is the key difference from the native HTML disabled attribute.

Feature disabled (HTML) aria-disabled="true"
Focusable with Tab No — removed from tab order Yes — still focusable
Announced by AT Yes — "dimmed" / "unavailable" Yes — "dimmed" / "unavailable"
Mouse click fires event No Yes — you must block it in JS
Form submits value No — excluded from submission Yes — included in submission
Can display tooltip on hover/focus No — focus removed, tooltip inaccessible Yes — element is focusable so tooltip works
Use on native form controls Preferred Only when you need to keep focus / show tooltip
Use on custom widgets N/A Required — native disabled not applicable

When to use aria-disabled instead of disabled

  • A tooltip explains why the button is disabled — you need the button to remain focusable so keyboard users can discover the tooltip
  • Custom composite widgets like role="button" on a <div> — the native attribute has no effect
  • Menu items in a dropdown — AT should be able to navigate to them to read "unavailable"

✓ Use aria-disabled (keep focusable)

<!-- Keeps focus + tooltip accessible -->
<button
  type="button"
  [attr.aria-disabled]="!canSubmit()"
  [attr.aria-describedby]="submit-tip"
  (click)="canSubmit() && submit()">
  Save
</button>
<div role="tooltip" id="submit-tip">
  Complete all required fields
</div>

✗ Native disabled (tooltip lost)

<!-- Keyboard user cannot reach tooltip -->
<button
  type="button"
  [disabled]="!canSubmit()"
  [attr.aria-describedby]="submit-tip">
  Save
</button>
<!-- Button not focusable -- tip never announced -->
<div role="tooltip" id="submit-tip">
  Complete all required fields
</div>
4.9

aria-hidden

aria-hidden
Boolean
absent / false — visible to AT true — hidden from AT

Removes an element and all its descendants from the accessibility tree. The element remains visually present — only AT is excluded. This is the ARIA equivalent of display:none for the accessibility tree only.

Common legitimate uses: decorative icons (<svg aria-hidden="true">), repeated visual elements that add noise (dividers, decorative images), duplicate content that would be read twice (off-screen clones).
🚫

Never put aria-hidden="true" on a focusable element. A button or link that is hidden from AT but focusable creates an invisible interactive element — keyboard users Tab to it but hear nothing. The element appears to be a ghost in the tab order. Always remove tabindex or use display:none / visibility:hidden if the element should be fully excluded from interaction.

⚠️

aria-hidden does not prevent keyboard focus. If an element is inside an aria-hidden="true" container, keyboard users can still Tab to any focusable descendants — they will just hear silence. Use a FocusTrap or inert attribute to also block focus.

The inert attribute (modern alternative)

HTML's inert attribute (widely supported since 2023) both removes elements from the accessibility tree AND prevents keyboard focus and pointer events. It is the correct tool for making background content inert behind a modal:

HTML — inert vs aria-hidden 
<!-- ✓ Modal open: background is inert (focus + AT both blocked) -->
<main [attr.inert]="isModalOpen() ? '' : null">
  ...page content (unfocusable while modal is open)...
</main>

<div role="dialog" aria-modal="true" [hidden]="!isModalOpen()">
  ...modal content...
</div>

<!-- ✓ Decorative icon: aria-hidden only (not focusable, so safe) -->
<svg aria-hidden="true" focusable="false">...</svg>

<!-- ✗ Wrong: focusable button inside aria-hidden container -->
<div aria-hidden="true">
  <button>Click me</button>  <!-- keyboard trap! -->
</div>
4.10

aria-current

aria-current
Token
page — current page in a nav step — current step in a wizard location — current location (breadcrumb) date — current date in a datepicker time — current time in a time widget true — current item (generic) false — not current (absent is equivalent)

Identifies the currently active item in a set of navigational elements or steps. The most common value is page for the active navigation link — it is the correct replacement for a visual "active" class.

Not for tabs or listboxes. Use aria-selected for tabs and option widgets. aria-current is for navigation — links, breadcrumbs, step indicators, pagination.
NVDA / JAWS / VoiceOver: announces "current page" / "current step" etc. appended to the link or element name.

Angular 21 — Active navigation link

HTML — RouterLinkActive with aria-current 
<nav aria-label="Primary navigation">
  <ul role="list">
    @for (link of navLinks(); track link.path) {
      <li>
        <a
          [routerLink]="link.path"
          routerLinkActive="active"
          [routerLinkActiveOptions]="{ exact: link.exact }"
          #rla="routerLinkActive"
          [attr.aria-current]="rla.isActive ? 'page' : null">
          {{ link.label }}
        </a>
      </li>
    }
  </ul>
</nav>

Breadcrumb with aria-current="location"

HTML — Accessible breadcrumb 
<nav aria-label="Breadcrumb">
  <ol>
    @for (crumb of breadcrumbs(); track crumb.path; let last = $last) {
      <li>
        @if (last) {
          <!-- Current page: not a link, aria-current="location" -->
          <span aria-current="location">{{ crumb.label }}</span>
        } @else {
          <a [routerLink]="crumb.path">{{ crumb.label }}</a>
          <span aria-hidden="true"> / </span>
        }
      </li>
    }
  </ol>
</nav>

Step indicator with aria-current="step"

HTML — Wizard step progress indicator 
<ol aria-label="Form progress">
  @for (step of steps(); track step.id; let i = $index) {
    <li
      [attr.aria-current]="currentStep() === step.id ? 'step' : null">
      {{ step.label }}
    </li>
  }
</ol>
<!-- Active step: "Step 2, Details, current step" -->
4.11

Angular 21 Signal Patterns for States

Angular 21's signal-based reactivity is a natural fit for ARIA states — signals are the source of truth, computed() derives display values, and [attr.aria-*] keeps the DOM in sync automatically.

Central state pattern: one signal, many aria attributes

TypeScript — Single state signal drives multiple ARIA attrs 
type LoadState = 'idle' | 'loading' | 'success' | 'error';

@Component({
  template: `
    <button
      type="button"
      [attr.aria-busy]="loadState() === 'loading' ? 'true' : null"
      [attr.aria-disabled]="loadState() === 'loading' ? 'true' : null"
      [attr.aria-label]="loadingLabel()"
      (click)="save()">
      @if (loadState() === 'loading') {
        <svg aria-hidden="true" class="animate-spin">...</svg>
      }
      {{ loadState() === 'loading' ? 'Saving…' : 'Save' }}
    </button>

    <div role="status" aria-live="polite" class="sr-only">
      {{ statusMessage() }}
    </div>
  `,
})
export class SaveButtonComponent {
  loadState = signal<LoadState>('idle');

  loadingLabel = computed(() =>
    this.loadState() === 'loading' ? 'Saving, please wait' : 'Save'
  );

  statusMessage = computed(() => {
    switch (this.loadState()) {
      case 'success': return 'Todo saved successfully.';
      case 'error':   return 'Save failed. Please try again.';
      default:         return '';
    }
  });

  async save() {
    this.loadState.set('loading');
    try {
      await this.todoService.save();
      this.loadState.set('success');
    } catch {
      this.loadState.set('error');
    }
  }
}

Effect-based aria-live announcement

TypeScript — LiveAnnouncer + effect() 
@Component({ /* ... */ })
export class TodoListComponent {
  private announcer = inject(LiveAnnouncer);

  todos = signal<Todo[]>([]);
  filter = signal<'all' | 'active' | 'done'>('all');

  filteredTodos = computed(() => {
    const f = this.filter();
    if (f === 'active') return this.todos().filter(t => !t.completed);
    if (f === 'done')   return this.todos().filter(t => t.completed);
    return this.todos();
  });

  constructor() {
    // Announce filter changes to screen reader users
    effect(() => {
      const count = this.filteredTodos().length;
      const label = this.filter();
      this.announcer.announce(
        `Showing ${count} ${label} todo${count !== 1 ? 's' : ''}`,
        'polite'
      );
    });
  }
}

Screen Reader Announcement Matrix

How major screen readers (May 2026) announce each ARIA state when an element receives focus:

State Value NVDA + Chrome JAWS + Chrome VoiceOver + Safari (macOS) TalkBack + Chrome (Android)
aria-expanded true "expanded" "expanded" "expanded" "expanded"
aria-expanded false "collapsed" "collapsed" "collapsed" "collapsed"
aria-checked true "checked" "checked" "checked" "checked"
aria-checked false "not checked" "unchecked" "unchecked" "not checked"
aria-checked mixed "partially checked" "partially checked" "mixed" "partially checked"
aria-selected true "selected" "selected" "selected" "selected"
aria-pressed true "pressed" "pressed" "selected" ⚠️ "pressed"
aria-pressed false "not pressed" "not pressed" (no announcement) ⚠️ "not pressed"
aria-invalid true "invalid entry" "invalid entry" reads aria-errormessage "invalid"
aria-busy true defers reading region defers reading region defers reading region defers reading region
aria-disabled true "dimmed" "unavailable" "dimmed" "disabled"
aria-hidden true element not in AT tree element not in AT tree element not in AT tree element not in AT tree
aria-current page "current page" "current page" "current page" "current page"
aria-current step "current step" "current step" "current step" "current step"
⚠️

VoiceOver inconsistency with aria-pressed: VoiceOver announces aria-pressed="true" as "selected" (not "pressed") and gives no announcement for aria-pressed="false". If your toggle button must be clearly understood on iOS/macOS, update the visible button label to reflect the state (e.g., "Dark mode: on") so the label alone communicates the state without relying solely on the ARIA state announcement.
