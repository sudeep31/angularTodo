Section 6 of 9 Custom ARIA Patterns in Angular 21

Complex interactive components — dialogs, tabs, comboboxes, data grids, tooltips, and disclosure widgets — require specific ARIA role hierarchies, keyboard contracts, and focus management to be accessible. This section walks through each pattern with complete Angular 21 implementations.

6.1

The APG Design Pattern Rule

The ARIA Authoring Practices Guide (APG) published by the W3C defines a design pattern for every complex widget. Each pattern specifies exactly three things:

  1. ARIA roles, properties & states — what roles to assign, what attributes are required
  2. Keyboard interaction contract — which keys do what; deviating from this breaks user expectations
  3. Focus management rules — where focus goes when the widget opens, closes, or the user navigates
💡

Rule: Before implementing any custom interactive component, look up its APG pattern at w3.org/WAI/ARIA/apg/patterns. If the component maps to an existing pattern, follow it exactly. If the component is genuinely novel, model it after the closest pattern. Never invent role structures or keyboard behaviours from scratch.

When to use CDK vs Custom Implementation

Component Angular CDK Solution Complexity
Modal Dialog cdkTrapFocus directive, A11yModule Low — CDK handles focus trapping
Tabs Manual implementation (no CDK tab widget as of v21) Medium — roving tabindex required
Combobox CdkListbox + CdkOption (CDK v17+) Medium — use CDK where possible
Data Grid CdkTable + manual grid keyboard High — complex keyboard model
Disclosure/Accordion Manual — small surface area Low — simple button + region pattern
Tooltip MatTooltip from Angular Material, or manual Low
6.2

Modal Dialog Pattern

role="dialog"
APG Pattern cdkTrapFocus
A dialog is an overlay window that traps focus inside it until dismissed. The user cannot Tab out of the dialog while it is open. Closing it must return focus to the element that triggered it. Use role="dialog" with aria-modal="true" to tell AT the rest of the page is inert.
Required: role="dialog" · aria-labelledby pointing to the dialog title · aria-modal="true" · Focus trap · Escape closes.

Keyboard contract (APG Dialog Pattern)

Tab
Move focus forward through focusable elements within the dialog — wraps at the end back to the first element
ShiftTab
Move focus backward — wraps from first element to last
Escape
Close the dialog and return focus to the trigger element
TypeScript — Angular 21 dialog component 
import { A11yModule, FocusTrap, FocusTrapFactory } from '@angular/cdk/a11y';

@Component({
  selector: 'app-confirm-dialog',
  standalone: true,
  imports: [A11yModule],
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    <div
      role="dialog"
      aria-modal="true"
      [attr.aria-labelledby]="'dialog-title-' + dialogId"
      [attr.aria-describedby]="'dialog-desc-' + dialogId"
      cdkTrapFocus
      cdkTrapFocusAutoCapture
      (keydown.escape)="close()"
    >
      <h2 [id]="'dialog-title-' + dialogId">{{ title() }}</h2>
      <p  [id]="'dialog-desc-'  + dialogId">{{ description() }}</p>
      <div>
        <button type="button" (click)="confirm()">Confirm</button>
        <button type="button" (click)="close()">Cancel</button>
      </div>
    </div>
  `,
})
export class ConfirmDialogComponent {
  readonly title         = input<string>('Confirm action');
  readonly description   = input<string>('');
  readonly confirmed      = output<void>();
  readonly dismissed      = output<void>();
  readonly dialogId       = crypto.randomUUID();

  // Track element that opened the dialog to restore focus on close
  private triggerEl: HTMLElement | null = null;

  open(trigger: HTMLElement): void {
    this.triggerEl = trigger;
  }

  confirm(): void {
    this.confirmed.emit();
    this.restoreFocus();
  }

  close(): void {
    this.dismissed.emit();
    this.restoreFocus();
  }

  private restoreFocus(): void {
    // Return focus to trigger after dialog is removed from DOM
    setTimeout(() => this.triggerEl?.focus());
  }
}
⚠️

Make the background inert: aria-modal="true" alone is not sufficient in all screen readers. In NVDA's Browse mode, users can still escape into the background DOM. Set [inert] or aria-hidden="true" on the <main> element when the dialog is open. Angular CDK's Dialog service handles this for you.

6.3

Tabs Pattern

role="tablist" / role="tab" / role="tabpanel"
APG Pattern Roving Tabindex
Tabs use a roving tabindex for keyboard navigation — only the active tab has tabindex="0"; all others have tabindex="-1". Arrow keys move between tabs; Tab moves into the active tabpanel. Each tab has aria-selected and aria-controls pointing to its panel.
Required: role="tablist" on container · role="tab" + aria-selected + aria-controls on each tab · role="tabpanel" + aria-labelledby on each panel · Roving tabindex · Arrow-key navigation between tabs

Keyboard contract (APG Tabs Pattern)

→ / ←
Move focus between tab buttons; activates the focused tab (automatic activation variant)
Home
Move focus to the first tab
End
Move focus to the last tab
Tab
Move focus to the active tab panel (exit the tab list into the panel content)
ShiftTab
From the panel, move focus back to the active tab
TypeScript — Angular 21 tabs component 
@Component({
  selector: 'app-tabs',
  standalone: true,
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    <div role="tablist" [attr.aria-label]="label()">
      @for (tab of tabs(); track tab.id; let i = $index) {
        <button
          role="tab"
          [id]="'tab-' + tab.id"
          [attr.aria-selected]="activeIndex() === i ? 'true' : 'false'"
          [attr.aria-controls]="'panel-' + tab.id"
          [tabindex]="activeIndex() === i ? 0 : -1"
          (click)="activate(i)"
          (keydown)="onKeydown($event, i)"
        >
          {{ tab.label }}
        </button>
      }
    </div>

    @for (tab of tabs(); track tab.id; let i = $index) {
      <div
        role="tabpanel"
        [id]="'panel-' + tab.id"
        [attr.aria-labelledby]="'tab-' + tab.id"
        [hidden]="activeIndex() !== i"
        tabindex="0"
      >
        <ng-container *ngTemplateOutlet="tab.content" />
      </div>
    }
  `,
})
export class TabsComponent {
  readonly tabs        = input<TabItem[]>([]);
  readonly label       = input<string>('');
  readonly activeIndex = signal(0);

  activate(index: number): void {
    this.activeIndex.set(index);
  }

  onKeydown(event: KeyboardEvent, current: number): void {
    const count = this.tabs().length;
    let next = current;

    switch (event.key) {
      case 'ArrowRight': next = (current + 1) % count;  break;
      case 'ArrowLeft':  next = (current - 1 + count) % count; break;
      case 'Home':        next = 0;          break;
      case 'End':         next = count - 1; break;
      default: return;
    }

    event.preventDefault();
    this.activate(next);

    // Move DOM focus to newly activated tab button
    const tabs = document.querySelectorAll<HTMLButtonElement>('[role="tab"]');
    tabs[next]?.focus();
  }
}
💡

Do not remove inactive panels from the DOM. Use [hidden] to hide inactive panels. Removing them with @if destroys component state and causes focus management issues when panels contain forms or interactive content. [hidden] keeps the DOM present but hides it visually and from AT.

6.4

Combobox / Autocomplete Pattern

role="combobox"
APG Pattern CdkListbox
A combobox is a text input paired with a popup listbox. The input uses role="combobox", aria-expanded, and aria-controls pointing to the listbox. Option focus is managed with aria-activedescendant — focus stays on the input while AT announces the highlighted option. Options use role="option" and aria-selected.
Required: role="combobox" on input · aria-expanded · aria-controls → listbox id · aria-activedescendant → highlighted option id · role="listbox" on popup · role="option" + aria-selected on each option

Keyboard contract (APG Combobox Pattern — List Autocomplete)

↓
Open popup if closed; move focus indicator to next option
↑
Move focus indicator to previous option; if at first option, return focus indicator to input
Enter
Select the focused option, close popup, return focus to input
Escape
Close popup without selecting; if popup already closed, clear input value
Home / End
Move cursor within input text (standard text editing behaviour)
HTML — Angular 21 combobox template (aria-activedescendant pattern) 
<div class="combobox-wrapper">
  <label [for]="comboboxId">{{ label() }}</label>

  <input
    [id]="comboboxId"
    type="text"
    role="combobox"
    [attr.aria-expanded]="isOpen() ? 'true' : 'false'"
    [attr.aria-controls]="listboxId"
    [attr.aria-autocomplete]="'list'"
    [attr.aria-activedescendant]="activeOptionId()"
    [value]="inputValue()"
    (input)="onInput($event)"
    (keydown)="onKeydown($event)"
  />

  @if (isOpen()) {
    <ul
      role="listbox"
      [id]="listboxId"
      [attr.aria-label]="label() + ' options'"
    >
      @for (opt of filteredOptions(); track opt.id) {
        <li
          role="option"
          [id]="'opt-' + opt.id"
          [attr.aria-selected]="opt.id === selectedId() ? 'true' : 'false'"
          (click)="select(opt)"
        >{{ opt.label }}</li>
      }
    </ul>
  }
</div>
6.5

Data Grid Pattern

role="grid"
APG Pattern Complex Keyboard
A grid is a composite widget containing a set of interactive cells. It differs from role="table" (which is presentational) in that cells can be edited, selected, or activated. Keyboard navigation moves through cells with arrow keys. The grid uses a roving tabindex — only one cell has tabindex="0" at a time.
Required: role="grid" on table · role="row" on tr · role="gridcell" on td · role="columnheader" / role="rowheader" on th · aria-rowcount, aria-colcount if virtualized · Arrow-key navigation between cells

Keyboard contract (APG Data Grid Pattern)

→ ← ↑ ↓
Move focus between cells in the grid
Page Up / Page Down
Move focus by a set number of rows up or down
Home
Move focus to first cell in the row; with Ctrl — first cell in first row
End
Move focus to last cell in the row; with Ctrl — last cell in last row
Enter / F2
Activate cell edit mode; Escape exits edit mode without saving
HTML — Angular 21 accessible data grid 
<table
  role="grid"
  aria-label="Todo list"
  [attr.aria-rowcount]="todos().length + 1"
  [attr.aria-colcount]="3"
>
  <thead>
    <tr role="row">
      <th role="columnheader" aria-sort="none"
          scope="col" tabindex="-1">Title</th>
      <th role="columnheader" scope="col" tabindex="-1">Status</th>
      <th role="columnheader" scope="col" tabindex="-1">Actions</th>
    </tr>
  </thead>
  <tbody>
    @for (todo of todos(); track todo.id; let rowIdx = $index) {
      <tr role="row"
          [attr.aria-rowindex]="rowIdx + 2">
        <td role="gridcell"
            [tabindex]="focusedCell()?.row === rowIdx && focusedCell()?.col === 0 ? 0 : -1"
            (keydown)="onCellKey($event, rowIdx, 0)"
        >{{ todo.title }}</td>

        <td role="gridcell"
            [tabindex]="focusedCell()?.row === rowIdx && focusedCell()?.col === 1 ? 0 : -1"
            (keydown)="onCellKey($event, rowIdx, 1)"
        >{{ todo.completed ? 'Done' : 'Pending' }}</td>

        <td role="gridcell"
            [tabindex]="focusedCell()?.row === rowIdx && focusedCell()?.col === 2 ? 0 : -1"
            (keydown)="onCellKey($event, rowIdx, 2)"
        >
          <button type="button"
                  [attr.aria-label]="'Delete ' + todo.title"
                  (click)="deleteTodo(todo)"
          >Delete</button>
        </td>
      </tr>
    }
  </tbody>
</table>
6.6

Disclosure & Accordion Pattern

<button aria-expanded> + aria-controls
APG Pattern Simple
A disclosure is a <button> that shows/hides a content region. The button has aria-expanded (true/false) and aria-controls pointing to the controlled region. An accordion is a group of disclosures. There is no dedicated ARIA role for accordion panels — they are just sections revealed by a button. The heading + button pattern is recommended.
Required per panel: <button aria-expanded="true|false" aria-controls="panelId"> · Controlled region has matching id; no special role needed.
HTML — Angular 21 accordion (heading-button pattern) 
<div class="accordion">
  @for (item of items(); track item.id) {
    <div class="accordion-item">
      <!-- Heading wraps the button for document outline -->
      <h3>
        <button
          type="button"
          [attr.aria-expanded]="item.open ? 'true' : 'false'"
          [attr.aria-controls]="'panel-' + item.id"
          (click)="toggle(item)"
        >
          {{ item.title }}
        </button>
      </h3>

      <!-- Panel: [hidden] keeps it in DOM (better than @if for animations) -->
      <div
        [id]="'panel-' + item.id"
        [hidden]="!item.open"
      >
        {{ item.content }}
      </div>
    </div>
  }
</div>
✅

Why [hidden] not @if: [hidden] keeps the panel DOM alive (important if it has form state), enables CSS transition animations, and is immediately re-discoverable if AT queries the DOM. @if destroys and recreates the panel, losing all state. Use @if only for panels that are genuinely resource-intensive and have no persistent state.

6.7

Tooltip Pattern

role="tooltip" + aria-describedby
APG Pattern
A tooltip provides additional descriptive text for an element, shown on hover and focus. The trigger element uses aria-describedby pointing to the tooltip container. The tooltip has role="tooltip". Focus must never move into the tooltip — it is purely informational.
Required: Trigger: aria-describedby="tooltipId" · Tooltip: role="tooltip" + matching id · Show on both hover AND focus · Never requires interaction · Never contains links or buttons
HTML — Angular 21 tooltip with keyboard support 
<!-- Tooltip trigger: shows on hover and focus -->
<button
  type="button"
  [attr.aria-describedby]="isTooltipVisible() ? 'info-tooltip' : null"
  (mouseenter)="showTooltip()"
  (mouseleave)="hideTooltip()"
  (focus)="showTooltip()"
  (blur)="hideTooltip()"
>
  ℹ Info
</button>

<!-- Tooltip: always in DOM; shown/hidden via CSS -->
<div
  id="info-tooltip"
  role="tooltip"
  [hidden]="!isTooltipVisible()"
>
  Mark this todo as complete to remove it from the active list.
</div>
🚫

Tooltip ≠ Accessible: Tooltips only appear on hover and focus — touch users get nothing. Do not put required information exclusively in a tooltip. If the information is needed for task completion, use visible text, <details>, or a disclosure widget instead. Tooltips are supplemental, not essential.

6.8

Pattern Compatibility Matrix

Screen reader support for complex ARIA patterns as of May 2026.

Pattern NVDA + Firefox JAWS + Chrome VoiceOver macOS Notes
Modal Dialog (cdkTrapFocus) ✅ ✅ ✅ Must set background inert for NVDA Browse mode
Tabs (roving tabindex) ✅ ✅ ✅ Arrow key nav works reliably; use [hidden] not @if
Combobox (aria-activedescendant) ⚠️ NVDA needs aria-live backup in older versions ✅ ✅ Test with real AT — combobox is historically the most unreliable pattern
Data Grid (role="grid") ✅ ✅ ⚠️ VoiceOver navigation differs; test thoroughly Complex — prefer role="table" if cells are not interactive
Disclosure (button aria-expanded) ✅ ✅ ✅ Most reliable pattern — widely supported
Accordion ✅ ✅ ✅ Heading + button structure important for document outline
Tooltip (role="tooltip") ✅ ✅ ⚠️ iOS VoiceOver requires explicit focus, not hover Not a replacement for visible text; supplemental only
🔬

Testing is non-optional for complex patterns. ARIA patterns have the highest variance of any accessibility feature across screen reader / browser combinations. Code review and automated axe scans cannot substitute for manual testing with NVDA + Firefox, JAWS + Chrome, and VoiceOver + Safari for every interactive component. Schedule AT testing as part of every feature sprint.
