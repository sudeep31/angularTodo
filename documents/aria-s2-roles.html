2.1

What is a Role?

An ARIA role is the single most important piece of information in the accessibility tree. It tells a screen reader what kind of thing an element is — a button, a heading, a dialog, a navigation landmark — and determines which keyboard interactions users expect, what the screen reader announces, and how the element participates in the page structure.

Every HTML element already has an implicit ARIA role derived from the tag name. The role attribute lets you override or supplement that when you build custom components:

HTML element Implicit ARIA role Screen reader announces How to use
<button>button"Save, button"<button type="button">Save</button>
<a href>link"Home, link"<a href="/home">Home</a>
<h1>–<h6>heading (level 1–6)"Main title, heading level 1"<h1>Main title</h1>
<nav>navigation"Navigation" (landmark)<nav aria-label="Primary">…</nav>
<main>main"Main" (landmark)<main id="main-content">…</main>
<ul> / <ol>list"List, 3 items"<ul><li>Buy milk</li></ul>
<li>listitem"Item 1 of 3"<li>Buy milk</li>
<input type="checkbox">checkbox"Accept terms, checkbox, unchecked"<input type="checkbox" id="t"><label for="t">Accept terms</label>
<input type="text">textbox"Name, edit text"<label for="n">Name</label><input type="text" id="n">
<select>listbox"Priority, listbox"<label for="p">Priority</label><select id="p">…</select>
<table>table"Todo table, 5 rows, 3 columns"<table aria-label="Todo list">…</table>
<div> / <span>generic (no role)Nothing announced<div>Container only</div>
⚠️

WAI-ARIA 1.2 defines 82 roles across five categories: Landmark, Widget, Document Structure, Live Region, and Abstract. Abstract roles are internal to the taxonomy — you must never use them in HTML. The remaining four categories are covered in this section.

2.2

Landmark Roles

Landmark roles carve the page into named navigable regions. Screen reader users rely on landmarks to jump between sections without reading every element — NVDA uses D, JAWS uses R, and VoiceOver uses W (rotor) to navigate landmarks.

Native HTML elements already map to landmark roles — always prefer the native element. The role attribute is only needed on non-semantic elements.

Role Native HTML Purpose Quantity per page NVDA/JAWS announces How to use
banner <header> (top-level) Site-wide header — logo, main nav, search Max 1 (top-level only) "Banner landmark" <header>…</header>
main <main> Primary page content — skip-to-main target Exactly 1 "Main landmark" <main id="main-content">…</main>
navigation <nav> Sets of navigation links Multiple allowed — label each with aria-label "Navigation landmark" / "Primary navigation landmark" <nav aria-label="Primary">…</nav>
complementary <aside> Supporting content tangentially related to main Multiple allowed "Complementary landmark" <aside aria-label="Filters">…</aside>
contentinfo <footer> (top-level) Site-wide footer — copyright, links, contact Max 1 (top-level only) "Content information landmark" <footer>…</footer>
search <search> (HTML 5.3) Search functionality Multiple allowed — label each "Search landmark" <search aria-label="Search todos">…</search>
form <form> with accessible name Form region (only a landmark when labelled) Multiple allowed — must have aria-label or aria-labelledby "Form landmark" (unnamed forms are not landmarks) <form aria-label="Add todo">…</form>
region <section> with accessible name Generic significant section — only use with a label Use sparingly — requires aria-label or aria-labelledby "Region landmark" / "Filters region landmark" <section aria-label="Filter panel">…</section>
💡

Label multiple landmarks of the same type. If you have two <nav> elements, add aria-label="Primary" and aria-label="Footer" so screen reader users know which is which. Unlabelled duplicate landmarks are one of the most common ARIA mistakes in Angular apps.

Angular 21 Landmark Pattern

HTML — Angular app.html 
<!-- Skip link — always first child of <body> -->
<a href="#main-content"
   class="sr-only focus:not-sr-only focus:absolute focus:top-2
          focus:left-2 focus:z-50 focus:bg-indigo-600 focus:text-white
          focus:px-4 focus:py-2 focus:rounded">
  Skip to main content
</a>

<!-- banner landmark: <header> as direct child of <body> -->
<header role="banner">
  <nav aria-label="Primary">...</nav>
</header>

<!-- main landmark: exactly one per page -->
<main id="main-content">

  <!-- filter sidebar: complementary landmark -->
  <aside aria-label="Todo filters">...</aside>

  <!-- search region -->
  <search aria-label="Search todos">
    <input type="search" name="q" />
  </search>

  <!-- form landmark: must have accessible name -->
  <form aria-label="Add new todo">...</form>

</main>

<!-- contentinfo landmark: <footer> as direct child of <body> -->
<footer role="contentinfo">...</footer>
2.3

Widget Roles

Widget roles represent interactive UI controls. They are the most complex and misused category. When you assign a widget role to a non-native element, you take on full responsibility for:

  • Adding an accessible name (aria-label or aria-labelledby)
  • Making the element keyboard focusable (tabindex="0")
  • Implementing all keyboard interactions the role implies (Enter, Space, arrows)
  • Managing all required ARIA states (aria-expanded, aria-checked, etc.)
⚠️

The Widget Role Tax. When you use role="button" on a <div> instead of a native <button>, you inherit zero of the native behaviour — no focus, no Enter/Space, no form submission, no disabled state. Native HTML elements are always the right choice. Use widget roles only when building genuinely custom composites that have no native equivalent.

Single-Value Widget Roles

These represent standalone interactive controls:

button Widget

A clickable control that triggers an action. Implicit in <button>, <input type="button">.

"Save changes, button"

Required ARIA: accessible name. Optional: aria-pressed (toggle), aria-expanded (disclosure), aria-disabled.

checkbox Widget

A two- or tri-state control. Implicit in <input type="checkbox">. Tri-state uses aria-checked="mixed".

"Accept terms, checkbox, unchecked"

Required ARIA: accessible name + aria-checked (true/false/mixed).

radio Widget

One option in a mutually exclusive group. Always nest inside radiogroup. Implicit in <input type="radio">.

"High, radio button, 1 of 3, checked"

Required ARIA: accessible name + aria-checked. Parent needs role="radiogroup".

switch Widget

An on/off toggle — semantically different from checkbox. Use for settings that take effect immediately (like a dark mode toggle).

"Dark mode, switch, on"

Required ARIA: accessible name + aria-checked (true/false — not "mixed").

link Widget

Navigates to a URL or location. Implicit in <a href>. Only use the role attribute if you cannot use a real anchor.

"Home, link"

Required ARIA: accessible name. tabindex="0" if not an <a>.

textbox Widget

Single-line text input. Implicit in <input type="text|email|tel|…">. Use aria-multiline="true" for multi-line.

"Search, edit text"

Required ARIA: accessible name via <label>.

searchbox Widget

Specialised textbox for search input. Implicit in <input type="search">. Announces "search box" instead of "edit".

"Search todos, search box"

Required ARIA: accessible name.

spinbutton Widget

Numeric range input (increment/decrement). Implicit in <input type="number">.

"Quantity, spin button, 1, minimum 0, maximum 100"

Required ARIA: aria-valuenow, aria-valuemin, aria-valuemax, accessible name.

slider Widget

Range control with a draggable thumb. Implicit in <input type="range">. Arrow keys must adjust value.

"Volume, slider, 60%"

Required ARIA: aria-valuenow, aria-valuemin, aria-valuemax. Optional: aria-valuetext for human-readable value.

progressbar Widget

Indicates progress of a task. When indeterminate (loading), omit aria-valuenow.

"Uploading, progress bar, 45%"

Required ARIA: accessible name. aria-valuenow + aria-valuemin + aria-valuemax for determinate.

scrollbar Widget

Custom scrollbar control. Rarely needed — native OS scrollbars are already accessible.

"Vertical scrollbar, 25%"

Required ARIA: aria-valuenow, aria-valuemin, aria-valuemax, aria-orientation, aria-controls.

separator (focusable) Widget

A focusable divider that can be moved (e.g. a resizable panel splitter). Non-focusable separators use the document structure variant.

"Separator, vertical, 30%"

Required ARIA: aria-valuenow, aria-valuemin, aria-valuemax, aria-orientation.

Composite Widget Roles

Composite widgets are containers for collections of child widgets. They use roving tabindex or aria-activedescendant to manage keyboard navigation within the group — only one element in the composite is in the tab order at a time.

Role Child roles Keyboard pattern Use for How to use
tablist tab → tabpanel Arrow keys between tabs, Tab into panel Tab navigation UI <div role="tablist" aria-label="Filters">…</div>
listbox option (+ group) Arrow keys, Space to select, Type-ahead Custom select dropdowns <ul role="listbox" aria-label="Priority">…</ul>
combobox textbox + listbox or tree Type to filter, Arrow down to list, Escape to close Autocomplete, Select+search <input role="combobox" aria-haspopup="listbox" aria-autocomplete="list">
menu / menubar menuitem, menuitemcheckbox, menuitemradio Arrow keys to navigate, Enter to activate, Escape to close Application menus (not navigation menus) <ul role="menu"><li role="menuitem">Edit</li></ul>
tree treeitem (+ group) Up/Down arrows, Right to expand, Left to collapse Hierarchical file browser, nested categories <ul role="tree"><li role="treeitem">Folder</li></ul>
treegrid row, gridcell Arrow keys in two dimensions, Enter/F2 to edit Hierarchical data grid <table role="treegrid" aria-label="Files">…</table>
grid row, gridcell, rowgroup Arrow keys in two dimensions, Enter/F2 to edit cells Spreadsheet-like editable data tables <table role="grid" aria-label="Todos">…</table>
radiogroup radio Arrow keys to move selection within group Groups a set of radio buttons <div role="radiogroup" aria-label="Priority">…</div>
group Any widget No navigation pattern — container only Logically groups related form controls <fieldset><legend>Contact</legend>…</fieldset>
toolbar button, checkbox, etc. Arrow keys between items, Tab out of toolbar Rich text editor toolbars, formatting bars <div role="toolbar" aria-label="Formatting">…</div>
spinbutton — Up/Down arrows to increment, Page Up/Down for large steps Already listed above — classified as both <input type="number" min="0" max="100" value="5">

Tooltip & Dialog Widget Roles

tooltip Widget

A popup that displays information about an element. Referenced by aria-describedby on the trigger. Does not receive focus.

Announced inline with the trigger: "Delete todo, button, Delete: Removes this todo item"

Required: trigger must have aria-describedby pointing to the tooltip's ID. Tooltip must be rendered in DOM (not CSS only).

dialog Widget

A modal or non-modal dialog window. Focus must move inside on open; Escape closes; focus returns to trigger on close.

"Confirm delete, dialog" (then reads first focusable element)

Required: accessible name via aria-labelledby. Optional: aria-describedby, aria-modal="true" (to suppress background from some AT).

alertdialog Widget

A dialog that contains an alert — requires immediate user response. Like dialog but also has live region behaviour (assertive).

"Delete all todos? Alert dialog" — interrupts immediately

Required: accessible name + aria-describedby pointing to the message.

💡

In Angular 21, use the CDK Dialog (CdkDialogModule) or Angular Material MatDialog for any modal — they handle focus trapping, Escape, aria-modal, and focus restoration automatically. Hand-rolling a modal is one of the most error-prone ARIA implementation tasks.

2.4

Document Structure Roles

Document structure roles describe the organisation and structure of content — not interactive controls. Most have native HTML equivalents. Use the native element first; fall back to the role only when semantic HTML is not available.

Role Native HTML What it means Screen reader behaviour How to use
heading <h1>–<h6> Section heading with level (aria-level) "Introduction, heading level 2" <h2>Introduction</h2>
list <ul>, <ol> An ordered or unordered collection of items "List with 5 items" <ul><li>Item 1</li></ul>
listitem <li> A single item in a list "Bullet, item 1 of 5" <li>Buy milk</li>
article <article> Independently distributable content (blog post, card) VoiceOver: "Article" (others may not announce) <article>…</article>
definition <dfn> The defining instance of a term Some SR: "definition" <dfn>ARIA</dfn>
term <dt> Term in a definition list "term" <dl><dt>ARIA</dt><dd>…</dd></dl>
img <img alt=""> A graphical element. Use on <figure> or <svg> needing a description. "[alt text], image" <img src="logo.png" alt="Company logo">
figure <figure> Self-contained content (image + caption) Some SR announce "figure" <figure><img src="c.png" alt="Chart"><figcaption>Chart 1</figcaption></figure>
table <table> Tabular data with row/column headers "Table with 5 rows and 3 columns" <table><caption>Todos</caption>…</table>
row <tr> A row of cells in a table or grid "Row 2 of 5" <tr><td>Buy milk</td></tr>
cell <td> A data cell in a table Cell content, then column header <td>Buy milk</td>
columnheader <th scope="col"> Column header cell Announces before cell data: "Priority, High" <th scope="col">Priority</th>
rowheader <th scope="row"> Row header cell Announces with row: "Buy groceries row" <th scope="row">Buy groceries</th>
note — A section of parenthetic or ancillary content Some SR: "note" <div role="note">See also: …</div>
blockquote <blockquote> A section quoted from another source NVDA: "block quote" (others may not) <blockquote>Quote text</blockquote>
code <code> A fragment of computer code NVDA (future): "code" wrapper <code>let x = 1</code>
paragraph <p> A paragraph of text Not typically announced as "paragraph" <p>Body text content here.</p>
generic <div>, <span> No semantic meaning — content passes through Nothing announced for the container itself <div>No semantics</div>
none / presentation — Strips element and children from AT tree Completely silent — covered in Section 2.6 <table role="none">…</table>
🚫

Never use role="heading" without aria-level. The default level is 2, which will disrupt your heading hierarchy if the surrounding context expects a different level. Always write role="heading" aria-level="3". Better still — use <h3>.

2.5

Live Region Roles

Live region roles are special roles that carry implicit aria-live behaviour. When content inside these elements changes, the screen reader announces it automatically — you do not need to add aria-live explicitly (though you can to override).

Role Implicit aria-live Implicit aria-atomic Use for Screen reader announces How to use
alert assertive true Error messages, critical notifications — interrupts the user immediately "Name is required, alert" — interrupts current speech <div role="alert">Error: Name is required</div>
status polite true Non-critical status updates ("3 todos remaining", "Saved") "3 todos remaining" — waits for silence <div role="status">3 todos remaining</div>
log polite false Chat logs, activity feeds — announces new entries only New entry text, politely <div role="log">…new messages…</div>
marquee off false Scrolling tickers — AT ignores by default (use sparingly) Not announced automatically <div role="marquee">Breaking news…</div>
timer off false Countdown/count-up timers — use aria-live="polite" on a separate announcement region Not announced automatically unless aria-live overridden <div role="timer" aria-live="polite">02:30</div>
⚠️

Timing trap with role="alert": If you inject an element with role="alert" into the DOM at the same moment the content appears, some screen readers miss it. The safe pattern is to always pre-render the element (empty) and then update its text content. Angular CDK's LiveAnnouncer implements this correctly — use it for all programmatic announcements.

Angular 21 — role="alert" Safe Pattern

HTML + TypeScript — Angular 
<!-- ✅ CORRECT: region pre-rendered in initial HTML, empty -->
<div
  role="alert"
  aria-live="assertive"
  aria-atomic="true"
  class="sr-only">
  {{ errorMessage() }}
</div>

<!-- ❌ WRONG: dynamically @if'd alert — many SR miss it -->
@if (errorMessage()) {
  <div role="alert">{{ errorMessage() }}</div>
}
TypeScript — Angular 21 with CDK LiveAnnouncer 
import { LiveAnnouncer } from '@angular/cdk/a11y';
import { inject, Component } from '@angular/core';

@Component({ /* ... */ })
export class TodoListComponent {
  private readonly liveAnnouncer = inject(LiveAnnouncer);

  async deleteTodo(title: string) {
    await this.todoService.delete();
    // Polite announcement — waits for current speech to finish
    await this.liveAnnouncer.announce(`Todo deleted: ${title}`, 'polite');
  }

  async handleError(msg: string) {
    // Assertive announcement — interrupts immediately
    await this.liveAnnouncer.announce(msg, 'assertive');
  }
}
2.6

role="none" and role="presentation"

role="none" and role="presentation" are synonyms. They remove the element's semantic meaning from the accessibility tree while leaving the element's subtree content visible to AT.

Use cases:

  • Stripping table layout semantics from a <table> used purely for visual layout (legacy HTML)
  • Removing list semantics from a <ul> used as a flex container (e.g., navigation bar where bullets are irrelevant)
  • Removing heading semantics from a styled <h2> inside a widget where the heading role conflicts with the widget role
🚫

role="none" is silently ignored when: the element has a global ARIA state/property (aria-label, aria-expanded, etc.), is focusable, or is a required child of a composite widget. Do not use it on interactive elements — the browser will ignore it.

HTML 
<!-- ✅ Strip layout-table semantics -->
<table role="none">
  <tr><td>Column A</td><td>Column B</td></tr>
</table>
<!-- AT sees the text "Column A Column B" without table structure -->

<!-- ✅ Remove list semantics from flex nav bar -->
<ul role="none" class="flex gap-4">
  <li role="none"><a href="/">Home</a></li>
</ul>
<!-- AT reads only the links, not "list with 1 item" -->

<!-- ❌ WRONG: ignored because element has aria-label -->
<div role="none" aria-label="Something">...</div>
<!-- aria-label causes role="none" to be ignored -->
2.7

Angular 21 Role Patterns

Binding Roles Dynamically with Signals

TypeScript — Angular 21 
@Component({
  selector: 'app-disclosure',
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    <!-- Toggle button with aria-expanded -->
    <button
      type="button"
      [attr.aria-expanded]="isOpen()"
      [attr.aria-controls]="panelId"
      (click)="toggle()">
      {{ label() }}
    </button>

    <!-- Controlled panel -->
    <div
      [id]="panelId"
      role="region"
      [attr.aria-labelledby]="triggerId"
      [hidden]="!isOpen()">
      <ng-content />
    </div>
  `,
})
export class DisclosureComponent {
  readonly panelId = `panel-${Math.random().toString(36).slice(2)}`;
  readonly triggerId = `trigger-${Math.random().toString(36).slice(2)}`;
  label = input<string>('');
  isOpen = signal(false);
  toggle() { this.isOpen.update(v => !v); }
}

Tab Panel Pattern — Roving tabindex

HTML — Angular template (ARIA tabs) 
<!-- tablist: parent container -->
<div role="tablist" aria-label="Todo filters">
  @for (tab of tabs(); track tab.id) {
    <button
      role="tab"
      [id]="'tab-' + tab.id"
      [attr.aria-selected]="activeTab() === tab.id"
      [attr.aria-controls]="'panel-' + tab.id"
      [tabindex]="activeTab() === tab.id ? 0 : -1"
      (click)="setTab(tab.id)"
      (keydown)="onTabKey($event, tab.id)">
      {{ tab.label }}
    </button>
  }
</div>

<!-- tabpanel -->
@for (tab of tabs(); track tab.id) {
  <div
    role="tabpanel"
    [id]="'panel-' + tab.id"
    [attr.aria-labelledby]="'tab-' + tab.id"
    [hidden]="activeTab() !== tab.id"
    tabindex="0">
    <ng-content [select]="'[tab=' + tab.id + ']'" />
  </div>
}
