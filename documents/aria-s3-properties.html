Section 3 of 9 ARIA Properties

3.1

Properties vs States

WAI-ARIA attributes are divided into two categories that behave differently in the accessibility tree:

Category Definition Changes at runtime? Examples
Properties Attributes that define the nature of an element — its name, description, or structural relationships. Generally set once and do not change as the user interacts. Rarely — set at render time aria-label, aria-labelledby, aria-describedby, aria-controls, aria-required, aria-haspopup, aria-level, aria-multiselectable
States Attributes that represent the current condition of an element — toggled or updated as the user interacts. Yes — updated dynamically aria-expanded, aria-checked, aria-selected, aria-pressed, aria-invalid, aria-busy, aria-disabled
💡

This section covers properties. States are covered in Section 4. In practice, the line can blur — aria-required rarely changes but is technically called a property, while aria-current updates during navigation but is also a state. WAI-ARIA 1.2 labels each attribute explicitly.

3.2

Naming Properties

The accessible name is what a screen reader announces as the label of an element. Without it, interactive elements are announced as "button" or "link" with no context — useless to a screen reader user.

Three ARIA naming properties exist. The W3C defines a strict priority order when multiple are present — called the Accessible Name and Description Computation (ANDC):

1
aria-labelledby References the text of another visible element by ID. Highest priority — overrides everything else including aria-label.
2
aria-label An explicit string attribute directly on the element. Overrides native label and content.
3
<label for> / <legend> / title / placeholder Native HTML labelling mechanisms — always prefer these over ARIA attributes.
4
Element text content The text inside the element itself (for buttons, links, headings). Used when nothing else is specified.
5
title attribute Lowest priority. Unreliable — not announced by all AT, not accessible to keyboard/touch users. Do not use as the sole accessible name.
3.3

aria-label

aria-label="string"
Naming

Provides an invisible string label directly on the element. The label is announced instead of the element's visible text or child content. It does not appear visually and is only available to assistive technology.

When to use: Icon-only buttons, form fields without visible labels, duplicate landmark regions, or when the visible label text is insufficient context.
When NOT to use: When the element already has a visible <label>, when the element's text content is already descriptive, or to change/override a visible label (use aria-labelledby instead — it can concatenate).

✓ Correct

<!-- Icon button: no visible text -->
<button
  type="button"
  aria-label="Delete todo">
  <svg aria-hidden="true">...</svg>
</button>

<!-- Two nav landmarks: unique labels -->
<nav aria-label="Primary">...</nav>
<nav aria-label="Footer">...</nav>

✗ Wrong

<!-- Redundant on element with visible text -->
<button
  aria-label="Delete todo button">
  Delete todo
</button>

<!-- aria-label on a div (no role = ignored) -->
<div aria-label="Section">
  ...no semantic role...
</div>

Angular 21 — Dynamic aria-label with Signals

TypeScript + HTML — Angular 21 
@Component({
  selector: 'app-todo-item',
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    <!-- Computed label includes todo title for context -->
    <button
      type="button"
      [attr.aria-label]="deleteLabel()"
      (click)="delete()">
      <svg aria-hidden="true">...</svg>
    </button>

    <!-- Toggle completion -->
    <button
      type="button"
      [attr.aria-label]="toggleLabel()"
      (click)="toggle()">
      <svg aria-hidden="true">...</svg>
    </button>
  `,
})
export class TodoItemComponent {
  todo = input.required<Todo>();

  // Computed labels include the todo title for full context
  deleteLabel = computed(() => `Delete todo: ${this.todo().title}`);
  toggleLabel = computed(() =>
    this.todo().completed
      ? `Mark incomplete: ${this.todo().title}`
      : `Mark complete: ${this.todo().title}`
  );

  delete() { /* ... */ }
  toggle() { /* ... */ }
}
3.4

aria-labelledby

aria-labelledby="id1 id2 ..."
Naming Relationship

Points to the ID(s) of one or more existing visible elements that serve as the label. The referenced elements' text is concatenated (space-separated) to form the accessible name. This is the highest-priority naming method — it overrides aria-label and all other mechanisms.

Key advantage: The label is visible on screen AND read by screen readers — no hidden text needed. Any change to the referenced element automatically updates the name.
Multiple IDs: You can concatenate multiple elements: aria-labelledby="title-id subtitle-id" — the browser reads both in order.
HTML — aria-labelledby patterns 
<!-- 1. Dialog labelled by its visible heading -->
<div role="dialog" aria-labelledby="dialog-title" aria-modal="true">
  <h2 id="dialog-title">Confirm delete</h2>
  <p id="dialog-desc">This action cannot be undone.</p>
</div>
<!-- Announces: "Confirm delete, dialog" -->

<!-- 2. Section region labelled by heading -->
<section aria-labelledby="filters-heading">
  <h2 id="filters-heading">Filter todos</h2>
  ...filter controls...
</section>

<!-- 3. Concatenating multiple labels -->
<div role="group" aria-labelledby="group-label group-hint">
  <span id="group-label">Priority</span>
  <span id="group-hint">(required)</span>
  ...radio buttons...
</div>
<!-- Announces: "Priority (required), group" -->

<!-- 4. Self-referential label (element references its own ID) -->
<h2 id="panel-title" aria-labelledby="panel-title">My heading</h2>
<!-- Valid but redundant — text content already IS the label -->
⚠️

The referenced ID must exist in the DOM. If the target element is conditionally rendered with @if and is currently hidden, the reference resolves to an empty string and the element becomes unlabelled. Use [hidden] to visually hide elements while keeping them in the DOM if they are referenced by aria-labelledby.

3.5

aria-describedby

aria-describedby="id1 id2 ..."
Description

Points to elements that provide an extended description of the current element — announced after the accessible name and role, with a brief pause. Unlike aria-labelledby (which replaces the name), this supplements it.

Rule of thumb: aria-labelledby answers "What is this?" — aria-describedby answers "What does it do / what should I know?"
Screen reader behaviour: NVDA/JAWS announce the description immediately after the role. VoiceOver announces it after a short pause and only when the user presses VO+Shift+M or waits.
HTML — aria-describedby patterns 
<!-- 1. Form field with helper text -->
<label for="todo-title">Todo title</label>
<input
  id="todo-title"
  type="text"
  aria-describedby="title-hint title-error"
  [attr.aria-invalid]="hasError()">
<p id="title-hint">Maximum 120 characters.</p>
<p id="title-error" role="alert">{{ errorMessage() }}</p>
<!-- Announces: "Todo title, edit text, Maximum 120 characters. Title is required." -->

<!-- 2. Button with tooltip description -->
<button
  type="button"
  aria-label="Delete todo"
  aria-describedby="delete-tooltip">
  <svg aria-hidden="true">...</svg>
</button>
<div id="delete-tooltip" role="tooltip">
  Permanently removes this todo item
</div>
<!-- Announces: "Delete todo, button, Permanently removes this todo item" -->

<!-- 3. Dialog with description -->
<div
  role="dialog"
  aria-labelledby="dlg-title"
  aria-describedby="dlg-body">
  <h2 id="dlg-title">Delete all todos?</h2>
  <p  id="dlg-body">This will permanently delete your 12 todos.</p>
</div>

aria-description (WAI-ARIA 1.3 preview)

WAI-ARIA 1.3 (in development) adds aria-description — an inline string property equivalent to aria-label but for descriptions, eliminating the need for a hidden off-screen element when only a descriptive string (not referenced visible text) is needed. Not yet in WAI-ARIA 1.2 — use aria-describedby pointing to a visually hidden element for now.

3.6

Naming Priority & Decision Guide

Use this decision guide every time you need to name an interactive element:

1
Can you use a native <label for>? For form inputs — always use a visible <label> element. It gives you accessible name + click target for free.
2
Is there existing visible text on the page? Reference it with aria-labelledby. The label stays in sync with the visible text automatically.
3
Is there no suitable visible text? Use aria-label with a descriptive string. Keep it short — it is the name, not a description.
4
Does the element have descriptive child text? For buttons, links, and headings — the text content is already the accessible name. No ARIA needed.
5
Never rely on title or placeholder alone title is not announced by all AT. placeholder disappears when the user types — it cannot be the only accessible name.
🚫

Never use placeholder as the accessible name for a text input. It fails WCAG 1.3.5 (Identify Input Purpose), disappears when the user starts typing, and has insufficient contrast in most browser default styles. Always pair it with a visible <label>.

Attribute Best for Avoid when
aria-label Icon buttons, duplicate landmarks, form fields with no visible label There is already visible text that works as a label; do not use to override a perfectly good visible label
aria-labelledby Dialogs (reference the heading), sections (reference a heading), groups (reference a visible group heading) The referenced element may not be in the DOM (dynamically removed)
aria-describedby Helper text under fields, error messages, tooltips, supplementary instructions in dialogs Brief labels — this is for secondary description, not primary naming
<label for> All visible form inputs — text, checkbox, radio, select, textarea Non-form elements (use aria-label or aria-labelledby instead)
3.7

Relationship Properties

Relationship properties communicate structural or logical connections between elements that are not inherent from the DOM structure — typically linking a control to its controlled element.

aria-controls="id"
Relationship

Indicates that an element controls another element — its interaction changes the content or visibility of the referenced element. Common on buttons, tabs, and comboboxes.

Screen reader support: JAWS reads "controls [target name]" on focus. NVDA and VoiceOver do not always announce it — do not rely solely on aria-controls for discoverability. Always pair with visual feedback.
<button aria-expanded="false" aria-controls="filter-panel">Filters</button>
<div id="filter-panel" [hidden]="!isOpen()">...</div>
aria-owns="id1 id2 ..."
Relationship

Declares that an element owns child elements that are not its DOM descendants — for example, a popup list that is rendered in a portal at the document root, logically belonging to the combobox that triggered it.

Use sparingly. aria-owns re-orders the accessibility tree. It can confuse AT if misused. Prefer DOM nesting whenever possible.
/* Combobox whose listbox is portalled to document.body */
<div role="combobox" aria-owns="listbox-id">...</div>
/* Inside Angular CDK Overlay (portal) */
<ul id="listbox-id" role="listbox">...</ul>
aria-flowto="id1 id2 ..."
Relationship

Provides an alternative reading order — lets the user follow a logical flow that differs from the DOM order. Very rarely needed. AT support is inconsistent. Fix reading order in the DOM instead.

Recommendation: Avoid. Fix DOM order to match visual order instead.
aria-activedescendant="id"
RelationshipWidget

Used in composite widgets (listbox, tree, grid) to indicate which child is the currently "active" item without moving DOM focus away from the container. The container keeps tabindex="0" and receives keyboard events; only the referenced child is announced as "active".

Alternative to roving tabindex. Use one or the other — never both. Angular CDK's ListKeyManager supports both patterns.
<ul role="listbox" tabindex="0"
   [attr.aria-activedescendant]="activeId()">
  @for (opt of options(); track opt.id) {
    <li role="option" [id]="opt.id">{{ opt.label }}</li>
  }
</ul>
aria-errormessage="id"
RelationshipWidget

References the element that contains the error message for an invalid input. Only meaningful when aria-invalid="true" is set on the same element. The error message element should not have role="alert" — use aria-errormessage instead so AT reads the error when the field is focused, not when it first appears.

WAI-ARIA 1.2 replaces the older pattern of pairing aria-describedby with role="alert". Both still work — but aria-errormessage is the recommended approach.
<input aria-invalid="true" aria-errormessage="title-err">
<p id="title-err">Title is required.</p>
3.8

Widget Configuration Properties

These properties configure the capabilities and constraints of widgets — they describe what a widget can do, not what it is currently doing (that is for states in Section 4).

Property Values Applies to What it communicates
aria-required true / false Form inputs, combobox User must provide a value before submitting. NVDA: "required". JAWS: "required field". Native HTML alternative: the required attribute.
aria-readonly true / false Textbox, spinbutton, listbox, grid The value is visible but cannot be modified. Different from aria-disabled — a read-only field is still focusable and its value is still submitted.
aria-haspopup menu / listbox / tree / grid / dialog / true Buttons, combobox triggers, menu items Activating this element will open a popup of the specified type. JAWS: "has popup". Use the specific type value (e.g., "menu") over "true".
aria-multiselectable true / false Listbox, grid, tree, tablist Multiple items can be selected simultaneously. NVDA: "multiselect". Users expect Shift+click and Ctrl+click to work.
aria-multiline true / false Textbox The textbox accepts multiple lines (like a <textarea>). Changes Enter key behaviour — Enter inserts newline instead of submitting.
aria-orientation horizontal / vertical / undefined Slider, scrollbar, separator, listbox, tablist, toolbar, tree Direction of the widget — affects which arrow keys navigate it. Default is horizontal for tablist, vertical for tree.
aria-level Integer ≥ 1 Heading, treeitem, row The hierarchical level of the element. Required when using role="heading" explicitly. Implicit in <h1>–<h6>.
aria-valuemin Number Slider, spinbutton, scrollbar Minimum allowed value. Announces: "minimum 0".
aria-valuemax Number Slider, spinbutton, scrollbar Maximum allowed value. Announces: "maximum 100".
aria-valuenow Number Slider, spinbutton, scrollbar, progressbar Current numeric value. Announces with aria-valuetext if present.
aria-valuetext String Slider, spinbutton, scrollbar Human-readable alternative to aria-valuenow. Use when the number alone is insufficient — e.g., "Monday" for a day-of-week slider. Overrides aria-valuenow for announcement.
aria-modal true / false Dialog, alertdialog Indicates content outside the dialog is inert. Suppresses background content in NVDA's browse mode and VoiceOver. Not a substitute for proper focus trapping in JavaScript.
aria-autocomplete none / list / inline / both Combobox, textbox Whether and how autocomplete suggestions are provided. list: suggestions in a popup. inline: suggestions inserted into the input. both: both.
aria-placeholder String Textbox, searchbox ARIA equivalent of the HTML placeholder attribute for custom inputs. Announced when the field is empty. Never the sole accessible name.
aria-rowcount / aria-colcount Integer (-1 = unknown) Table, grid, treegrid Total number of rows/columns when the table is virtualised and not all rows are in the DOM. Use -1 when count is unknown.
aria-rowindex / aria-colindex Integer ≥ 1 Row, cell, gridcell, columnheader, rowheader Position within a virtualised table — required when aria-rowcount is set.
aria-setsize Integer (-1 = unknown) Listitem, option, treeitem, radio, tab Total number of items in the set. Required when items are virtualised and not all are in the DOM.
aria-posinset Integer ≥ 1 Listitem, option, treeitem, radio, tab Position of the item within the set. Required when aria-setsize is set.
aria-sort ascending / descending / other / none Columnheader, rowheader Current sort direction of the column/row. Set on the active sort header only — others get aria-sort="none".
aria-keyshortcuts String (e.g., "Alt+N") Any interactive element Keyboard shortcut(s) that activate or navigate to the element. AT may announce it; only use when the shortcut is actually implemented and visible somewhere in the UI.
aria-roledescription String Any element with a role Overrides the role name that AT announces — use to provide a domain-specific name for a custom widget (e.g., "Slide" for a carousel item). Use sparingly and with caution.
⚠️

Virtualised tables require aria-rowcount + aria-rowindex. If you render a large dataset with CDK virtual scroll (only 50 rows in the DOM out of 5,000), you must set aria-rowcount="5000" on the table/grid and aria-rowindex on each visible row. Without this, screen readers announce "row 1 of 50" instead of "row 1 of 5,000".

3.9

Drag-and-Drop Properties

WAI-ARIA 1.2 provides two properties for communicating drag-and-drop state to AT. However, these alone do not make drag-and-drop accessible — you must also provide a keyboard-only alternative (e.g., move buttons, keyboard shortcut).

Property Values Purpose
aria-grabbed true / false / undefined Deprecated in WAI-ARIA 1.1 — do not use. Previously indicated whether an element was grabbed for drag. Now use custom solutions with aria-roledescription and live announcements.
aria-dropeffect copy / move / link / execute / popup / none Deprecated in WAI-ARIA 1.1 — do not use. Use live region announcements and keyboard alternatives instead.

Accessible Drag-and-Drop in Angular 21 (CDK)

HTML — Accessible drag-and-drop with keyboard fallback 
<!-- Each draggable item has keyboard Move buttons -->
@for (todo of todos(); track todo.id; let i = $index) {
  <div
    cdkDrag
    role="listitem"
    [attr.aria-label]="todo.title + ', item ' + (i + 1) + ' of ' + todos().length">

    <span>{{ todo.title }}</span>

    <!-- Keyboard-only move controls (visually hidden for mouse users) -->
    <button
      type="button"
      class="sr-only focus:not-sr-only"
      [disabled]="i === 0"
      [attr.aria-label]="'Move up: ' + todo.title"
      (click)="moveUp(i)">Move up</button>

    <button
      type="button"
      class="sr-only focus:not-sr-only"
      [disabled]="i === todos().length - 1"
      [attr.aria-label]="'Move down: ' + todo.title"
      (click)="moveDown(i)">Move down</button>
  </div>
}
💡

After a keyboard move, announce the new position using LiveAnnouncer: "Buy groceries moved to position 2 of 5". This is essential for screen reader users to confirm the move succeeded.

3.10

Angular 21 Patterns for ARIA Properties

The [attr.aria-*] binding pattern

In Angular, use [attr.aria-*] to bind ARIA properties dynamically. This ensures the attribute is only present in the DOM when it has a value — Angular removes attributes that resolve to null or undefined.

HTML — Angular attribute binding for ARIA 
<!-- aria-labelledby: reference a heading in the same template -->
<section [attr.aria-labelledby]="sectionHeadingId()">
  <h2 [id]="sectionHeadingId()">{{ sectionTitle() }}</h2>
  ...
</section>

<!-- aria-controls: reference a panel by signal-derived ID -->
<button
  type="button"
  [attr.aria-controls]="panelId"
  [attr.aria-expanded]="isOpen()"
  (click)="toggle()">
  Filters
</button>

<!-- aria-sort: conditionally null (attribute removed) -->
<th
  scope="col"
  [attr.aria-sort]="sortColumn() === 'title' ? sortDirection() : null">
  Title
</th>
<!-- When sortColumn() !== 'title', aria-sort is not in the DOM -->

Generating stable IDs for ARIA relationships

TypeScript — Angular 21 stable ID pattern 
import { inject } from '@angular/core';

// ✅ Angular 21: use the built-in IdGenerator for stable IDs
import { IdGenerator } from '@angular/cdk/a11y';

@Component({ /* ... */ })
export class FormFieldComponent {
  private idGen = inject(IdGenerator);

  // Stable IDs that survive SSR hydration
  fieldId  = this.idGen.getId();
  hintId   = this.idGen.getId();
  errorId  = this.idGen.getId();
}
⚠️

Never use Math.random() for ARIA IDs in SSR apps. The server and client generate different random values, causing a hydration mismatch. Use Angular CDK's IdGenerator or a counter-based approach that produces the same IDs on both server and client.

Complete Form Field Component — all naming properties together

HTML — Angular 21 accessible form field 
<div class="form-field">

  <!-- Native label: primary accessible name -->
  <label [for]="fieldId">
    {{ label() }}
    @if (required()) {
      <span aria-hidden="true"> *</span>
      <span class="sr-only">(required)</span>
    }
  </label>

  <!-- Input: wired to label, hint, and error -->
  <input
    [id]="fieldId"
    [type]="type()"
    [attr.aria-required]="required() || null"
    [attr.aria-invalid]="hasError() ? 'true' : null"
    [attr.aria-errormessage]="hasError() ? errorId : null"
    [attr.aria-describedby]="hintId">

  <!-- Hint: always present, referenced by aria-describedby -->
  <p [id]="hintId" class="hint">{{ hint() }}</p>

  <!-- Error: always in DOM, empty when valid -->
  <p
    [id]="errorId"
    aria-live="polite"
    class="error">
    {{ hasError() ? errorMessage() : '' }}
  </p>

</div>
